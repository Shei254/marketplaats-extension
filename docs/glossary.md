# Glossary

Domain terms for the Marktplaats relisting extension. Kept current as the design is grilled.

| Term | Definition |
|---|---|
| **Marktplaats** | Large Dutch online classifieds marketplace (owned by Adevinta). Our target platform. Site: marktplaats.nl. |
| **Advertentie (Listing / Ad)** | A single item a seller has posted for sale on Marktplaats. |
| **Relist / "Opnieuw plaatsen"** | Marktplaats action that refreshes a listing's timestamp so it re-appears near the top of recency-sorted results. The core action our product automates. |
| **Bump** | Generic term for any action that pushes a listing back up in ranking (relist is the free form; paid promotion is another). |
| **Verkopen Omhoog / Topper / Dagtopper** | Marktplaats's *paid* promotion products that raise a listing's visibility. Distinct from the free relist. |
| **dotb.io** | Reference competitor: a Chrome browser extension automating Vinted (repost/bump, multi-account, AI). Client-side, subscription-based. Our stated inspiration. |
| **POC (Proof of Concept)** | First deliverable: an icon next to a user's own listing that lets them relist it once. |
| **Execution model** | *Undecided.* Whether relists run client-side (browser extension in the user's session) or server-side (cloud backend acting on the user's behalf). See ADR-0001. |
| **Content script** | Extension code injected into the marktplaats.nl page DOM; how we would render the icon and read listing data client-side. |
| **App account** | A user's identity *in our product* (for auth + subscription). Distinct from their Marktplaats account. |
| **Marketplace session** | The user's authenticated Marktplaats login (cookies/tokens) that any relist action must ride on. |

| **Mijn Advertenties** | The seller's own ad-management view on Marktplaats, where they see and control (edit/delete/post) their own listings. |
| **Internal-API replay** | The extension calling Marktplaats's own private endpoints (list my ads, delete ad, create ad) in the background using the user's logged-in session cookies — the engine behind both relist surfaces (ADR-0004). |
| **Popup panel** | The extension's toolbar-triggered UI listing all of the user's ads with a per-ad relist action; no page navigation. |
| **Durable snapshot** | The full pre-delete capture of an ad (all fields + photo blobs) stored in `chrome.storage.local`, enabling retry/restore in the delete-first flow (ADR-0003). |
| **CSRF/session token** | A token Marktplaats may require on internal write calls; replaying it correctly is an open POC spike. |

| **User (App account)** | An identity in our product, issued by Keycloak. One human = one User. Separate from any Marktplaats account. |
| **CurrentUser** | The caller of the request being handled, resolved from the validated access token: the IdP subject and nothing else. Distinct from **User (App account)**, which is a row — a CurrentUser exists on the first authenticated request, before any row does. _Avoid_: principal, session user. |
| **UserRef** | The **User (App account)** row behind a CurrentUser. Asking for one is what provisions it, so a handler that declares it cannot run before the account and its Subscription exist (T11); one that only needs to know who is calling declares a CurrentUser and touches no database. _Avoid_: user id, account id. |
| **First login** | The first request carrying an IdP subject no `app_user` row holds. This API is a resource server and nobody signs in *to* it, so there is no login event of its own — this is the moment T11 provisions the account and its default-tier Subscription, in one transaction. _Avoid_: signup, registration. |
| **MarktplaatsAccount (association)** | A Marktplaats account associated with a User — label + MP id only, **never credentials/session**. Supports multi-account. |
| **Subscription** | The User's plan, mirrored from Stripe via webhooks; carries tier/status/period. |
| **Tier** | A named plan in **our** catalog (Postgres): quota-per-period, max MarktplaatsAccounts, feature flags, plus a `stripePriceId` linking it to the Stripe Price that carries amount/currency/interval. Admin-managed. Named in two spellings that are not interchangeable — `code` is the stable handle the seed upserts on and a client may branch on, `name` is display text an operator may rewrite — and `/api/me` sends both, so nothing brands a plan by its label (T17). _Avoid_: Package, Product — and **Plan**, which since ADR-0019 names a different thing: a Tier joined with its Stripe Price. |
| **Entitlement** | Limits/features derived from a Subscription's Tier (relists per period, max MP accounts, feature flags) — what quota checks read. Resolved from our Tier table, **never** from Stripe on the hot path. Resolved from a **Tier**, not from a User (T12): which tier somebody is on is the Subscription's to say. Carries no window and no rate — the **Quota period** is on the Subscription and pacing is the **SafetyPolicy**'s. ADR-0025 gives `bulk` a value rather than a boolean — `{"upTo": 10}` — which is the shape this column was built for, and `V8__seed_bulk_entitlement.sql` is the first seed to use it; `scheduling` is still named and still unbuilt. _Avoid_: plan limits, quota (which is one field of it). |
| **RelistEvent (UsageRecord)** | The backend's record of what a relist it authorized turned out to be — one per reservation a report resolved, refunds included, which is what makes it the breakage canary rather than the count. Its unique `reservationId` is also what makes `/complete` idempotent: the second report for one authorization conflicts there, and the **first report decides** (T14). _Avoid_: usage row (the unit is on the UsageReservation). |
| **UsageReservation** | The quota unit itself, held from `authorize` until `complete` settles or refunds it. Usage in a period is the reservations in it that were not refunded, so an in-flight relist already counts. Taken only after every check has passed, and under the lock on the caller's Subscription that makes checking and spending one decision (T13). _Avoid_: hold, pending usage, in-flight relist. |
| **Settle / Refund** | What a report does to the reservation it names (T14). `SUCCESS` and `FAILED_AFTER_DELETE` **settle** it — the ad was deleted, so the unit stays spent — and `FAILED_BEFORE_DELETE` **refunds** it, since nothing was consumed on Marktplaats. Both are terminal, and a *report* writes a RelistEvent either way; a **Reconciliation** refund writes none. _Avoid_: commit, cancel, void. |
| **Reconciliation** | The scheduled job that refunds a UsageReservation nothing ever reported on, once its RelistAuthorization has been expired longer than the **grace window** (T15). The one guess in the enforcement path, and the weaker claim of the two: a report arriving afterwards settles the unit back, because it is the only account of what happened on Marktplaats. Writes no RelistEvent — the three outcomes are things the extension observed, and this observed only silence. _Avoid_: expiry sweep, cleanup, garbage collection. |
| **Grace window** | How long past a RelistAuthorization's `expiresAt` a reservation is left alone before Reconciliation hands its unit back — how long we wait for a report, not how long a relist takes. Configuration, not a constant (T15). _Avoid_: timeout, TTL (that is the authorization's ~45s). |
| **Quota remaining** | What a tier grants per period less the units the current period is holding, **never below zero** — one subtraction with three readers: the gate's refusal, `/complete`'s answer (T14) and `/api/me`'s (T17). It is `enforcement`'s to answer, since the units are counted from its table and nowhere else, so the display asks rather than counting. The clamp is not cosmetic: an operator may lower a tier's quota under a subscriber (ADR-0014). _Avoid_: quota left over, credits. |
| **RelistAuthorization** | A short-lived signed backend OK the extension must obtain before a gated relist (ADR-0007). Its `jti` is the id of the reservation it was issued against. |
| **SafetyPolicy** | Per-User rate limits and caps — harm-reduction for the user's own Marktplaats account (ADR-0008), never a throttle protecting ours. The last check of the gate (T16), and the only one that is not about entitlement: it asks how fast, not how much. It counts **attempts** — every reservation taken, whatever became of it — where quota counts what a period still holds. Human-like *jitter* is not here and cannot be: a backend can refuse a call that came too soon, it cannot make one arrive at a human-shaped moment (T46, client-side). **A batch is not something it can see**: `authorize` arrives one ad at a time whether a person clicked or a queue did, which is why `batch` is a field the caller states rather than a pattern this infers (ADR-0025). _Avoid_: rate limiter, throttle. |
| **Pacing rail** | One of the two rules SafetyPolicy refuses on: the **minimum interval** between consecutive relists, and the **burst limit** inside a sliding **burst window** (T16). The longer of the two answers a refusal, and the burst rail is measured from the cap-th most recent relist rather than the oldest in the window. Both are configuration, and a window shorter than limit × interval is a rail arithmetic can never reach. **Never a tier lever** (ADR-0025): the rails exist for the user's own Marktplaats account, so selling a paying tier a faster hour would be selling them a higher chance of a ban — a bigger plan buys more relists per **period** and the same ten per hour as everybody else. _Avoid_: cooldown (that is what the user sees), quota (that is per period, not per minute). |
| **Retry after** | Whole seconds until a rate-limited caller may relist again, rounded **up** and carried by `RATE_LIMITED` alone (T16). A number rather than a date, because it is rendered as a countdown; in the body rather than the HTTP header of that name. _Avoid_: `resetAt`, which is the quota's date and a different refusal's. |

| **Bulk repost** | Selecting several of your own ads and reposting them in one act (ADR-0025). Built by T68 (2026-09-05, decided the same day); what remains of that ticket is the walk through `click-through.md`, which needs real ads. **Not a second relist mechanic**: each ad is an ordinary delete-first relist that authorizes, spends a unit and reports its own outcome, and what is new is only that something other than a finger presses the button. A paid **Entitlement** — `features.bulk` — which the popup gates and `authorize` refuses. _Avoid_: mass repost, bump all, repost all. |
| **Batch** | The run itself: an ordered queue of listing ids persisted in `chrome.storage.local`, owned by the service worker and advanced by a `chrome.alarms` wake. It outlives the popup closing and the worker being evicted, and **deliberately does not outlive a browser restart** — alarms persist, so stopping it is a decision rather than a limit. Distinct from a **selection**, which is what is ticked on the screen and is transient. _Avoid_: job, bulk session, queue (that is what a batch is made of, not what it is). |
| **Bulk window** | The randomised gap between two postings *inside a batch* — 30–60s, served beside the single-repost `pacing` window it does not replace. Wider because that gap is **watched** and this one is not; floored at 30s because `chrome.alarms` clamps there, and a window entirely below the clamp is not a jittered gap but a metronome (ADR-0025). _Avoid_: bulk delay, bulk interval, cooldown. |
| **Batch cap** | How many ads one selection may hold: `min(quotaRemaining, features.bulk.upTo)`. Pro's `upTo` is 10 — one **burst window** exactly, so a Pro batch never sleeps mid-run — and Power's is 25, which is two burst waits and about two hours. **The client's cap and never the API's**: `authorize` sees one ad at a time and has nothing to count a batch with, so the backend enforces *whether* and the popup enforces *how many*. _Avoid_: bulk limit (that is the burst rail), quota (that is the period's). |

| **Default tier** | The Tier flagged `isDefault`, auto-assigned to every User on first login, and the tier a terminal subscription end falls back to (ADR-0018). Currently the free tier. **There is always one**: `TierCatalog.defaultTier()` throws without it and `ProvisionOnFirstLogin` catches nothing, so a catalog with no default provisions nobody. Removing the *free tier* is therefore **setting the default tier's quota to 0**, not unsetting the flag (ADR-0019) — every user is still provisioned and every relist is refused by `QUOTA_EXCEEDED`. _Avoid_: Free plan as a special case. |
| **Quota period** | The `[periodStart, periodEnd)` window on a Subscription that usage is counted within. Copied from Stripe for payers, rolled monthly from signup for free users. `resetAt` = `periodEnd`. A free window is rolled **when the gate next reads it** (T13), in whole calendar months anchored on the Subscription's creation — anchoring on the window being replaced would re-anchor on February's clamped 28th and walk the reset day earlier. A Stripe-owned window is only ever moved by its webhook (T20). |
| **Display state** | The unsigned `GET /api/me` snapshot (status, tier, quota, resetAt, features) the UI renders from. Explicitly **not** an authorization — the relist path ignores it (ADR-0007) — and it spends nothing, so a popup opened five times costs no quota. Every authenticated caller gets one: a lapsed payer and an exhausted user are *shown* their state rather than refused, and `401` is the only other answer (T17). It is the backend's sixth module, named for this term, because composing it from four others in any of them would be a dependency cycle. _Avoid_: cached grant, session state. |
| **Golden payload** | A byte-exact snapshot of a request the internal-API layer emits (method, URL, headers, body including form field order), asserted with `fetch` stubbed. Freezes the working Marktplaats calls so the code around them can be refactored (ADR-0015). |
| **Client config** | The backend-served document of endpoint paths, CSRF extraction rules and the pacing window that overrides the extension's hardcoded defaults, fetched by the worker from `GET /api/client-config` and kept under `clientConfig` in `chrome.storage.local` (T27). **A patch, not a configuration**: the defaults ship in the build and this says only where an operator departed from them, so `{"schemaVersion":1}` is the healthy answer and the API holds no copy of anything to go stale. Strictly data, never executable (ADR-0013) — the CSRF `mode` is an enum at both ends, so there is no fifth branch a document could ask for. _Avoid_: remote code, feature flags. |
| **Endpoint override** | A tester's local pin of one or more endpoint paths, stored under `endpointOverrides` by the `__setEndpoints` dev hook. Only the keys named are stored, so an endpoint left alone still follows the build's default. The top of three resolution sources — built-in defaults, then the **Client config**, then this — and **it wins**, which is T27's open call decided: an override is typed by hand in a `build:dev` bundle by somebody working a path out live, and a served document must not undo that from a distance mid-session. |
| **Breakage canary** | The `/complete` outcome mix. A rising `FAILED_BEFORE_DELETE` rate means Marktplaats changed something and a client-config hotfix is needed. |
| **Ownership detection** | Deciding, on an arbitrary marktplaats.nl page, that an ad belongs to the current user before injecting a Repost control. **Open spike** — to be pinned against the real DOM. |

| **Iteration 1** | Everything up to and including a user paying and being unlocked, running on one machine against Stripe **test mode** — four vertical slices, each ending at a click-through script (ADR-0016). Explicitly not the finish line: reaching anybody else is **Go-Live**. _Avoid_: MVP, v1. |
| **Go-Live** | The milestone that makes Iteration 1 reachable by a stranger: deployment, domain, TLS, a production Keycloak realm, live Stripe keys, Stripe Tax and VAT registration, client-side pacing (#54), the Web Store listing, the final brand name, and CI. The 2026-08-13 backlog contained no ticket for any of it. _Avoid_: launch, release — those are events, this is work. |
| **Vertical slice** | A unit of work ending at a state of the product a human can demonstrate, rather than at a layer that can be unit-tested (ADR-0016). Cut this way deliberately, accepting rework, because usability is only answerable by looking. _Avoid_: milestone, epic. |
| **Click-through script** | The numbered manual test a slice must pass: what to click, and what must be on the screen — shaped like [`live-testing.md`](live-testing.md). **A slice is done when the script has been walked, not when its tickets close** (ADR-0016). _Avoid_: smoke test, QA pass, acceptance criteria. |
| **Plan** | What a buyer chooses: a **Tier** joined with the Stripe Prices its `tier_price` rows name — quota and flags ours, amount and currency Stripe's. Neither half alone is one, which is why `GET /api/plans` reads both. Only a **published** Tier carrying at least one price is a Plan, so the free tier is a Tier and never a Plan: there is nothing there to buy. Since T62 a Plan may carry several prices, one per **Rhythm**. _Avoid_: using it for **Tier**, the catalog row underneath it. |
| **Rhythm** | How often one of a Plan's prices recurs, in Stripe's vocabulary — `month`, `year` (T62, T66). **The handle for one of a Plan's prices**, and the only one anybody uses: "the annual Pro" names a Price without naming its id, which is why `tier_price` is keyed on it, why `POST /api/checkout` requires one beside the tier code, and why a plan card draws a button per rhythm rather than a toggle. Monthly and annual Pro are **one Plan sold at two rhythms**, not two Tiers to keep in step. A plan is created at all of its rhythms in one submit (T66); adding one afterwards, or repricing one, is the same act in Stripe — a new tagged Price. _Avoid_: billing period (that is the **Quota period**), frequency, cadence. |
| **Draft tier** | A Tier a `price.created` webhook synced before anybody said what it grants: quota 0, `published = false` (ADR-0019). Cannot be bought and appears on no plan card. Publishing one is an admin setting its quota. _Avoid_: pending, unconfigured. |
| **Dunning** | Stripe retrying a failed payment — `past_due`, `unpaid`, `incomplete`. Since ADR-0018 this is the **only** remaining meaning of `SUBSCRIPTION_INACTIVE`: the subscriber keeps their tier and is refused, because a successful retry gives it straight back. The 402 copy is therefore "update your card", never "resubscribe". _Avoid_: lapsed, expired — those now fall back to free instead. |
| **Fallback to default** | What a *terminal* subscription end does: the webhook moves the row to the **Default tier** with status `active`, and the **Quota period** back to our monthly roll (ADR-0018). An ex-customer becomes a free user rather than someone with less than a stranger. `stripeCustomerId` is kept, `stripeSubscriptionId` cleared. _Avoid_: downgrade (also a paid-to-paid move), cancellation (Stripe's event, not our reaction to it). |
| **Payment method** | What a buyer picks on the Stripe Checkout page: iDEAL, PayPal, card, SEPA. A setting on the Stripe **account** and never a parameter in code — `OpenCheckout` sets no `payment_method_types`, so adding one is a dashboard checkbox rather than a deploy (ADR-0006, amended 2026-09-01). Distinct from the **processor**, which is Stripe and of which there is exactly one: PayPal is a method *inside* Stripe, not a second processor, and every mirror, webhook, portal and price column in this system assumes that. _Avoid_: payment provider — conflating method with processor is what makes "add PayPal alongside Stripe" read as either a checkbox or a quarter of work. |
| **Brand name** | What users see — **Bumpr**, provisionally — held in one root `brand.json` and templated at build time into `manifest.template.json`, the popup and `apps/web`. Distinct from **`mprelist`**, the internal identifier frozen into `com.mprelist`, `@mprelist/*`, the Keycloak realm and its three clients, and the Postgres database. Renaming the brand is one file and a rebuild; renaming the identifier is a repo-wide refactor and a `down -v`. Never lead the brand with "Marktplaats" — Web Store policy forbids trademark use that implies endorsement. _Avoid_: conflating the two. |
