# Glossary

Domain terms for the Marktplaats relisting extension. Kept current as the design is grilled.

| Term | Definition |
|---|---|
| **Marktplaats** | Large Dutch online classifieds marketplace (owned by Adevinta). Our target platform. Site: marktplaats.nl. |
| **Advertentie (Listing / Ad)** | A single item a seller has posted for sale on Marktplaats. |
| **Gereserveerd (Reserved ad)** | An **Advertentie** its seller has marked as promised to a buyer — Marktplaats's own flag, set by `PUT /seller/api/reserve-ad` and carried by both the list row and the capture. A repost is delete-and-recreate (ADR-0002) and the new ad comes back *without* it, so [ADR-0028](adr/0028-a-repost-puts-back-what-it-can.md) puts it back: an item the seller promised must not return to the open market as a side-effect of our own mechanic. **Never called "a reservation"** — that noun is taken, by the quota unit below, in the same source file. The quota concept keeps the noun ("a reservation", "the unit"); the ad concept is always the Dutch adjective or "reserved ad", the way **Advertentie**, **Mijn Advertenties** and **"Opnieuw plaatsen"** already disambiguate. Code keeps `reserved` and `reserveAd`, because those are Marktplaats's names and the internal-API layer mirrors them. _Avoid_: reservation, hold, on hold. |
| **Relist / "Opnieuw plaatsen"** | Marktplaats action that refreshes a listing's timestamp so it re-appears near the top of recency-sorted results. The core action our product automates. |
| **Repost (what users read)** | The same act as **Relist**, in the word the product says out loud. [ADR-0029](adr/0029-unlimited-is-null-and-zero-still-grants-nothing.md) makes the split deliberate: every string a user reads says *repost* — the button already did — and every internal identifier keeps *relist*, because `POST /api/relist/authorize`, `RelistEvent`, `RelistGate`, `relistQuotaPerPeriod` and the golden payloads are expensive to move and invisible to the person pressing the button. **The same shape as Brand name vs `mprelist`**, and written down for the same reason: a split nobody recorded is read as a mistake and "fixed" in both directions. Before T73 the two were mixed without a rule — the strip said "2 of 3 relists left" one line above a button labelled Repost, and `/admin`'s quota field said both in one field. **T74 was the sweep and it is done**: nothing a user or an operator reads says *relist*, and `/admin`'s suite opens every panel that screen has and holds the whole rendered text to it rather than checking fields one at a time. **In Dutch the verb is _herplaatsen_** (noun _herplaatsing_), and it is the only *name* the product gives the act — *"opnieuw plaatsen"* is Marktplaats's own name and belongs to **Relist** above, the way `mprelist` belongs to the identifier and not to the brand. **One deliberate exception**, and it is not a lapse: the row's hover text reads *"Verwijder ‘…’ en plaats de advertentie opnieuw"*, because that sentence exists to say a repost **deletes first** (ADR-0002) and the single verb is exactly what hides it. Spelling the two steps out is not a second name for them. _Avoid_: bump (that is any ranking push, paid or free), re-list, re-post, and *"opnieuw plaatsen"* as a name for the act. |
| **Bump** | Generic term for any action that pushes a listing back up in ranking (relist is the free form; paid promotion is another). |
| **Verkopen Omhoog / Topper / Dagtopper** | Marktplaats's *paid* promotion products that raise a listing's visibility. Distinct from the free relist. |
| **dotb.io** | Reference competitor: a Chrome browser extension automating Vinted (repost/bump, multi-account, AI). Client-side, subscription-based. Our stated inspiration. |
| **POC (Proof of Concept)** | First deliverable: an icon next to a user's own listing that lets them relist it once. |
| **Execution model** | *Undecided.* Whether relists run client-side (browser extension in the user's session) or server-side (cloud backend acting on the user's behalf). See ADR-0001. |
| **Content script** | Extension code injected into the marktplaats.nl page DOM; how we would render the icon and read listing data client-side. |
| **App account** | A user's identity *in our product* (for auth + subscription). Distinct from their Marktplaats account. |
| **Marketplace session** | The user's authenticated Marktplaats login (cookies/tokens) that any relist action must ride on. |

| **Mijn Advertenties** | The seller's own ad-management view on Marktplaats, where they see and control (edit/delete/post) their own listings. |
| **Internal-API replay** | The extension calling Marktplaats's own private endpoints (list my ads, delete ad, create ad) in the background using the user's logged-in session cookies — the engine behind both relist surfaces (ADR-0004). |
| **Popup panel** | The extension's toolbar-triggered UI listing all of the user's ads with a per-ad relist action; no page navigation. |
| **Durable snapshot** | The full pre-delete capture of an ad (all fields + photo blobs) stored in `chrome.storage.local`, enabling retry/restore in the delete-first flow (ADR-0003). |
| **CSRF/session token** | A token Marktplaats may require on internal write calls; replaying it correctly is an open POC spike. |

| **User (App account)** | An identity in our product, issued by Keycloak. One human = one User. Separate from any Marktplaats account. |
| **CurrentUser** | The caller of the request being handled, resolved from the validated access token: the IdP subject and nothing else. Distinct from **User (App account)**, which is a row — a CurrentUser exists on the first authenticated request, before any row does. _Avoid_: principal, session user. |
| **UserRef** | The **User (App account)** row behind a CurrentUser. Asking for one is what provisions it, so a handler that declares it cannot run before the account and its Subscription exist (T11); one that only needs to know who is calling declares a CurrentUser and touches no database. _Avoid_: user id, account id. |
| **First login** | The first request carrying an IdP subject no `app_user` row holds. This API is a resource server and nobody signs in *to* it, so there is no login event of its own — this is the moment T11 provisions the account and its default-tier Subscription, in one transaction. _Avoid_: signup, registration. |
| **MarktplaatsAccount (association)** | A Marktplaats account associated with a User — label + MP id only, **never credentials/session**. Supports multi-account. |
| **Subscription** | The User's plan, mirrored from Stripe via webhooks; carries tier/status/period. |
| **Tier** | A named plan in **our** catalog (Postgres): quota-per-period, max MarktplaatsAccounts, feature flags, plus a `stripePriceId` linking it to the Stripe Price that carries amount/currency/interval. Admin-managed. Named in two spellings that are not interchangeable — `code` is the stable handle the seed upserts on and a client may branch on, `name` is display text an operator may rewrite — and `/api/me` sends both, so nothing brands a plan by its label (T17). `code` is stable **once there is a Price to freeze it**: on a tier with none it is re-derived from the name on every edit, because Stripe holds the only other copy and a priceless tier has given it none ([ADR-0031](adr/0031-the-free-tier-is-the-one-without-a-price.md)). Nobody types one either way. **Deletable since [ADR-0032](adr/0032-every-tier-is-deletable-and-an-empty-catalog-is-a-state.md)** — every row, the **Default tier** and the last one included — which took a nullable `subscription.tier_id`, a **Tier-less subscription** as a real state, and a **Stripe cleanup** queue, because a Price that outlives its tier still carries `metadata.tier_code` and would re-adopt it. _Avoid_: Package, Product — and **Plan**, which since ADR-0019 names a different thing: a Tier joined with its Stripe Price. |
| **Entitlement** | Limits/features derived from a Subscription's Tier (relists per period, max MP accounts, feature flags) — what quota checks read. Resolved from our Tier table, **never** from Stripe on the hot path. Resolved from a **Tier**, not from a User (T12): which tier somebody is on is the Subscription's to say. Carries no window and no rate — the **Quota period** is on the Subscription and pacing is the **SafetyPolicy**'s. Its quota may be **absent** rather than a number, which is an **Unlimited tier** (T73); `0` remains a coherent grant and means the opposite. ADR-0025 gives `bulk` a value rather than a boolean — `{"upTo": 10}` — which is the shape this column was built for, and `V8__seed_bulk_entitlement.sql` is the first seed to use it; `scheduling` is still named and still unbuilt. _Avoid_: plan limits, quota (which is one field of it). |
| **RelistEvent (UsageRecord)** | The backend's record of what a relist it authorized turned out to be — one per reservation a report resolved, refunds included, which is what makes it the breakage canary rather than the count. Its unique `reservationId` is also what makes `/complete` idempotent: the second report for one authorization conflicts there, and the **first report decides** (T14). _Avoid_: usage row (the unit is on the UsageReservation). |
| **UsageReservation** | The quota unit itself, held from `authorize` until `complete` settles or refunds it. Usage in a period is the reservations in it that were not refunded, so an in-flight relist already counts. Taken only after every check has passed, and under the lock on the caller's Subscription that makes checking and spending one decision (T13). _Avoid_: hold, pending usage, in-flight relist. |
| **Settle / Refund** | What a report does to the reservation it names (T14). `SUCCESS` and `FAILED_AFTER_DELETE` **settle** it — the ad was deleted, so the unit stays spent — and `FAILED_BEFORE_DELETE` **refunds** it, since nothing was consumed on Marktplaats. Both are terminal, and a *report* writes a RelistEvent either way; a **Reconciliation** refund writes none. _Avoid_: commit, cancel, void. |
| **Reconciliation** | The scheduled job that refunds a UsageReservation nothing ever reported on, once its RelistAuthorization has been expired longer than the **grace window** (T15). The one guess in the enforcement path, and the weaker claim of the two: a report arriving afterwards settles the unit back, because it is the only account of what happened on Marktplaats. Writes no RelistEvent — the three outcomes are things the extension observed, and this observed only silence. _Avoid_: expiry sweep, cleanup, garbage collection. |
| **Grace window** | How long past a RelistAuthorization's `expiresAt` a reservation is left alone before Reconciliation hands its unit back — how long we wait for a report, not how long a relist takes. Configuration, not a constant (T15). _Avoid_: timeout, TTL (that is the authorization's ~45s). |
| **Quota remaining** | What a tier grants per period less the units the current period is holding, **never below zero** — one subtraction with three readers: the gate's refusal, `/complete`'s answer (T14) and `/api/me`'s (T17). It is `enforcement`'s to answer, since the units are counted from its table and nowhere else, so the display asks rather than counting. The clamp is not cosmetic: an operator may lower a tier's quota under a subscriber (ADR-0014). **No Repost control is ever locked on this number** (T32): it goes back up without its holder acting, because a failure before the delete hands its unit back and so does **Reconciliation** — a button disabled on `0` here is one a refund has already made wrong. It still *caps* a **Bulk repost** selection (ADR-0025), which is a different question — how many may go in one act, not whether the feature is open. `null` on an **Unlimited tier**, where there is no subtraction to do — which is why every reader of this number is nullable at both ends since T73. _Avoid_: quota left over, credits. |
| **Unlimited tier** | A **Tier** whose repost quota is `null`: no cap within a period, and the one grant that is an absence rather than a number ([ADR-0029](adr/0029-unlimited-is-null-and-zero-still-grants-nothing.md)). **Never spelled `0`**, which is the whole decision — `0` is what a **Draft tier** is adopted at, what "there is no free tier" is written as on the **Default tier**, and what the auto-publish rule tests against, so a `0` meaning unlimited would give every new account everything by the same gesture that withdraws the free tier. Never `-1` either: `Math.max(0, -1 - held)` is `0`, so that tier would refuse every repost while reading as a gate that works. **Unlimited per period and not per hour** — the reservation, the **SafetyPolicy** rails and the **RelistEvent** are all unchanged, so the holder still gets the same ten an hour as everybody else (ADR-0025), and the **Breakage canary** still sees them. On the **Default tier** it is allowed and warned about, because a self-hosted single-user deployment is exactly that row. _Avoid_: infinite, uncapped, unmetered — the last is false, since a unit is still reserved and reported. |
| **RelistAuthorization** | A short-lived signed backend OK the extension must obtain before a gated relist (ADR-0007). Its `jti` is the id of the reservation it was issued against. |
| **SafetyPolicy** | Per-User rate limits and caps — harm-reduction for the user's own Marktplaats account (ADR-0008), never a throttle protecting ours. The last check of the gate (T16), and the only one that is not about entitlement: it asks how fast, not how much. It counts **attempts** — every reservation taken, whatever became of it — where quota counts what a period still holds. Human-like *jitter* is not here and cannot be: a backend can refuse a call that came too soon, it cannot make one arrive at a human-shaped moment (T46, client-side). **A batch is not something it can see**: `authorize` arrives one ad at a time whether a person clicked or a queue did, which is why `batch` is a field the caller states rather than a pattern this infers (ADR-0025). _Avoid_: rate limiter, throttle. |
| **Pacing rail** | One of the two rules SafetyPolicy refuses on: the **minimum interval** between consecutive relists, and the **burst limit** inside a sliding **burst window** (T16). The longer of the two answers a refusal, and the burst rail is measured from the cap-th most recent relist rather than the oldest in the window. Both are configuration, and a window shorter than limit × interval is a rail arithmetic can never reach. **Never a tier lever** (ADR-0025): the rails exist for the user's own Marktplaats account, so selling a paying tier a faster hour would be selling them a higher chance of a ban — a bigger plan buys more relists per **period** and the same ten per hour as everybody else. _Avoid_: cooldown (that is what the user sees), quota (that is per period, not per minute). |
| **Retry after** | Whole seconds until a rate-limited caller may relist again, rounded **up** and carried by `RATE_LIMITED` alone (T16). A number rather than a date, because it is rendered as a countdown; in the body rather than the HTTP header of that name. _Avoid_: `resetAt`, which is the quota's date and a different refusal's. |

| **Bulk repost** | Selecting several of your own ads and reposting them in one act (ADR-0025). Built by T68 (2026-09-05, decided the same day) and **withdrawn from the popup on 2026-09-07** ([ADR-0027](adr/0027-the-popup-stops-offering-bulk-repost.md)) for go-live scope, taking T68's outstanding `click-through.md` walk with it to T70. **Not a second relist mechanic**: each ad is an ordinary delete-first relist that authorizes, spends a unit and reports its own outcome, and what is new is only that something other than a finger presses the button. A paid **Entitlement** — `features.bulk` — which the popup gates and `authorize` refuses. **The term still names everything under it while no surface offers it**: the entitlement grants, the queue runs and `authorize` refuses, exactly as below — what is gone is the tick, and T70 is what puts it back. _Avoid_: mass repost, bump all, repost all. |
| **Batch** | The run itself: an ordered queue of listing ids persisted in `chrome.storage.local`, owned by the service worker and advanced by a `chrome.alarms` wake. It outlives the popup closing and the worker being evicted, and **deliberately does not outlive a browser restart** — alarms persist, so stopping it is a decision rather than a limit. Distinct from a **selection**, which is what is ticked on the screen and is transient. Still real while **Bulk repost** is withdrawn, and startable only by `__startBatch` in a dev build. _Avoid_: job, bulk session, queue (that is what a batch is made of, not what it is). |
| **Bulk window** | The randomised gap between two postings *inside a batch* — 30–60s, served beside the single-repost `pacing` window it does not replace. Wider because that gap is **watched** and this one is not; floored at 30s because `chrome.alarms` clamps there, and a window entirely below the clamp is not a jittered gap but a metronome (ADR-0025). _Avoid_: bulk delay, bulk interval, cooldown. |
| **Batch cap** | How many ads one selection may hold: `min(quotaRemaining, features.bulk.upTo)`. Pro's `upTo` is 10 — one **burst window** exactly, so a Pro batch never sleeps mid-run — and Power's is 25, which is two burst waits and about two hours. **The client's cap and never the API's**: `authorize` sees one ad at a time and has nothing to count a batch with, so the backend enforces *whether* and the popup enforces *how many*. An operator still sets `upTo` in `/admin` (ADR-0026) while the popup is not offering bulk, where it caps nothing anybody can reach (ADR-0027). _Avoid_: bulk limit (that is the burst rail), quota (that is the period's). |
| **Selection** | What is ticked on the ad list right now, before there is a **Batch** to work through it — transient, held only by the open popup, and **it survives the search box**. Picking ten ads out of forty is a job for the search, so a query that silently unticked what had already been chosen would make the only workable way to do it impossible; instead the count keeps counting the ads a query has taken off the screen and the header names them, because reposting deletes first (ADR-0003) and a batch holding ads the user cannot see is the one surprise here that cannot be undone. *Select all* is **additive** and capped by what is *left* of the **Batch cap**, taking ads in the order the list is showing them — pressing it after ticking two rows by hand adds eight rather than discarding those two. A selection outlives a stopped batch that has not been dismissed: the summary of the last run and the offer to start the next are two different things in one strip, and the run must never be the reason a fresh selection has no button. **No surface makes one since 2026-09-07** ([ADR-0027](adr/0027-the-popup-stops-offering-bulk-repost.md)) — the one term here that is currently a word for something nobody can do, kept because T70 brings the screen back rather than rebuilds it. _Avoid_: batch (that is the run), checked rows, marked ads. |

| **Free tier** | The one **Tier** that has no Stripe Price, and therefore the one nobody can buy — derived from `tier_price` being empty, never a flag ([ADR-0031](adr/0031-the-free-tier-is-the-one-without-a-price.md)). **There is exactly one, and nothing enforces it**: both creation paths require a price — `NewPlanInStripe` refuses an empty rhythm list, and the sync adopts a tier *from* a Price — so a second one is unsayable rather than forbidden, the same shape as `isDefault`. An operator never *creates* one — both creation paths require a price — but since [ADR-0032](adr/0032-every-tier-is-deletable-and-an-empty-catalog-is-a-state.md) they may **delete** it, which is a different act from withdrawing the free grant: a quota of `0` keeps a row for everybody to sit on and deleting does not. "At most one" is still unsayable, and now for one reason rather than two — nothing can make a priceless tier at all, which was always the half doing the work. Mostly they **edit** the row `V2__seed_tier_catalog.sql` left them, setting its name (and with it its `code`, which is the one tier whose handle may move), quota, features and place in the **Catalog order**. It is today also the **Default tier**, and the two are not the same claim: *free* is about having no price, *default* is about where new accounts land. A free tier that is not the default is reachable by nobody, and the default tier may be given a price — warned about, since that ends its freeness and freezes its code permanently. **Never "the Free plan"**: a **Plan** is a Tier joined with a Price, and this is the one Tier that can never be one. _Avoid_: free plan, the default tier (a different fact about the same row today), starter tier. |
| **Default tier** | The Tier flagged `isDefault`, auto-assigned to every User on first login, and the tier a terminal subscription end falls back to (ADR-0018). Currently the **Free tier**, which is a coincidence of configuration and not the same fact — *default* says where new accounts land, *free* says the row has no Price ([ADR-0031](adr/0031-the-free-tier-is-the-one-without-a-price.md)). **There was always one until [ADR-0032](adr/0032-every-tier-is-deletable-and-an-empty-catalog-is-a-state.md)**, and the guarantee was never a constraint: `tier_single_default` is partial-unique and says *at most* one, while *at least* one held only because the seed wrote one, `makeDefault` moves the flag rather than clearing it, and nothing deleted. T77 makes every tier deletable, so `defaultTier()` answers an `Optional`, `ProvisionOnFirstLogin` writes a **Tier-less subscription** rather than throwing, and the catalog may have no default at all — a state and not corruption. `PUT /api/admin/tiers/{code}/default` is what ends it, adopting every orphan in the same transaction, because it is the sole writer of the flag and therefore the only moment "no default exists" stops being true. Removing the *free tier* is therefore **setting the default tier's quota to 0**, not unsetting the flag (ADR-0019) — every user is still provisioned, the popup draws every Repost button locked before anything is clicked (T32), and a relist attempted anyway is refused by `QUOTA_EXCEEDED`. **That spelling survived being challenged** ([ADR-0029](adr/0029-unlimited-is-null-and-zero-still-grants-nothing.md)): a `0` that meant *unlimited* would have made the switch that withdraws the free tier the switch that hands every new account — and every ex-customer, since a terminal end falls back here — an **Unlimited tier**. The row may be set unlimited deliberately, with a warning naming that reach; a self-hosted single-user deployment is the case that earns it. _Avoid_: Free plan as a special case. |
| **Quota period** | The `[periodStart, periodEnd)` window on a Subscription that usage is counted within. Copied from Stripe for payers, rolled monthly from signup for free users. `resetAt` = `periodEnd`. A free window is rolled **when the gate next reads it** (T13), in whole calendar months anchored on the Subscription's creation — anchoring on the window being replaced would re-anchor on February's clamped 28th and walk the reset day earlier. A Stripe-owned window is only ever moved by its webhook (T20). |
| **Display state** | The unsigned `GET /api/me` snapshot (status, tier, quota, resetAt, features) the UI renders from. Explicitly **not** an authorization — the relist path ignores it (ADR-0007) — and it spends nothing, so a popup opened five times costs no quota. It decides how a control *looks* and never whether a relist may happen, and since T32 it may be locked on only where it cannot move under the user: the **grant**, never the **Quota remaining**. Every authenticated caller gets one: a lapsed payer and an exhausted user are *shown* their state rather than refused, and `401` is the only other answer (T17). It is the backend's sixth module, named for this term, because composing it from four others in any of them would be a dependency cycle. _Avoid_: cached grant, session state. |
| **Golden payload** | A byte-exact snapshot of a request the internal-API layer emits (method, URL, headers, body including form field order), asserted with `fetch` stubbed. Freezes the working Marktplaats calls so the code around them can be refactored (ADR-0015). |
| **Client config** | The backend-served document of endpoint paths, CSRF extraction rules and the pacing window that overrides the extension's hardcoded defaults, fetched by the worker from `GET /api/client-config` and kept under `clientConfig` in `chrome.storage.local` (T27). **A patch, not a configuration**: the defaults ship in the build and this says only where an operator departed from them, so `{"schemaVersion":1}` is the healthy answer and the API holds no copy of anything to go stale. Strictly data, never executable (ADR-0013) — the CSRF `mode` is an enum at both ends, so there is no fifth branch a document could ask for. _Avoid_: remote code, feature flags. |
| **Endpoint override** | A tester's local pin of one or more endpoint paths, stored under `endpointOverrides` by the `__setEndpoints` dev hook. Only the keys named are stored, so an endpoint left alone still follows the build's default. The top of three resolution sources — built-in defaults, then the **Client config**, then this — and **it wins**, which is T27's open call decided: an override is typed by hand in a `build:dev` bundle by somebody working a path out live, and a served document must not undo that from a distance mid-session. |
| **Breakage canary** | The `/complete` outcome mix. A rising `FAILED_BEFORE_DELETE` rate means Marktplaats changed something and a client-config hotfix is needed. |
| **Ownership detection** | Deciding, on an arbitrary marktplaats.nl page, that an ad belongs to the current user before injecting a Repost control. **Open spike** — to be pinned against the real DOM. |

| **Iteration 1** | Everything up to and including a user paying and being unlocked, running on one machine against Stripe **test mode** — four vertical slices, each ending at a click-through script (ADR-0016). Explicitly not the finish line: reaching anybody else is **Go-Live**. _Avoid_: MVP, v1. |
| **Go-Live** | The milestone that makes Iteration 1 reachable by a stranger: deployment, domain, TLS, a production Keycloak realm, live Stripe keys, Stripe Tax and VAT registration, client-side pacing (#54), the Web Store listing, the final brand name, and CI. The 2026-08-13 backlog contained no ticket for any of it. _Avoid_: launch, release — those are events, this is work. |
| **Vertical slice** | A unit of work ending at a state of the product a human can demonstrate, rather than at a layer that can be unit-tested (ADR-0016). Cut this way deliberately, accepting rework, because usability is only answerable by looking. _Avoid_: milestone, epic. |
| **Click-through script** | The numbered manual test a slice must pass: what to click, and what must be on the screen — shaped like [`live-testing.md`](live-testing.md). **A slice is done when the script has been walked, not when its tickets close** (ADR-0016). _Avoid_: smoke test, QA pass, acceptance criteria. |
| **Plan** | What a buyer chooses: a **Tier** joined with the Stripe Prices its `tier_price` rows name — quota and flags ours, amount and currency Stripe's. Neither half alone is one, which is why `GET /api/plans` reads both. Only a **published** Tier carrying at least one price is a Plan, so the free tier is a Tier and never a Plan: there is nothing there to buy. Since T62 a Plan may carry several prices, one per **Rhythm**. _Avoid_: using it for **Tier**, the catalog row underneath it. |
| **Rhythm** | How often one of a Plan's prices recurs, in Stripe's vocabulary — `month`, `year` (T62, T66). **The handle for one of a Plan's prices**, and the only one anybody uses: "the annual Pro" names a Price without naming its id, which is why `tier_price` is keyed on it, why `POST /api/checkout` requires one beside the tier code, and why a plan card draws a button per rhythm rather than a toggle. Monthly and annual Pro are **one Plan sold at two rhythms**, not two Tiers to keep in step. A plan is created at all of its rhythms in one submit (T66); adding one afterwards, or repricing one, is the same act in Stripe — a new tagged Price. _Avoid_: billing period (that is the **Quota period**), frequency, cadence. |
| **Draft tier** | A Tier a `price.created` webhook synced before anybody said what it grants: quota 0, `published = false` (ADR-0019). Cannot be bought and appears on no plan card. Publishing one is an admin setting its quota — and since [ADR-0029](adr/0029-unlimited-is-null-and-zero-still-grants-nothing.md) that is a rule rather than a habit: **a published tier grants something**, so quota 0 stays the marker of a tier nobody has decided about and cannot be sold. _Avoid_: pending, unconfigured. |
| **Catalog order** | The sequence the **Tier** catalog is held in, set by an operator dragging rows in `/admin` and rendered by both screens that list tiers ([ADR-0030](adr/0030-the-catalog-order-is-the-operators.md)). **Every tier carries a place, including the ones no buyer sees** — the free tier and every **Draft tier** — and the plan cards render the subsequence of it that is published, so a tier taken off sale for an afternoon comes back where it was. Before T75 it was not an order anybody chose: `order by relist_quota_per_period, code`, spelled identically in two queries, which the `V2` seed disguised as creation order by granting 3, 50 and 200 in that sequence. **A property of the catalog and never of a row** — the same shape as `isDefault`, and for the same reason: moving one tier moves others, so it is written by one route carrying the whole sequence (`PUT /api/admin/tiers/order`) and is *not* a field on **AdminTier**, where a number beside an already-ordered array would be one fact spelled twice. A tier the Stripe sync drafts goes **last**, since nobody has placed it. _Avoid_: plan order (a **Plan** is a Tier joined with a Price, and unpublished rows carry a place while being no Plan at all), display order (`display` is the backend module this never touches), rank, priority. |
| **Dunning** | Stripe retrying a failed payment — `past_due`, `unpaid`, `incomplete`. Since ADR-0018 this is the **only** remaining meaning of `SUBSCRIPTION_INACTIVE`: the subscriber keeps their tier and is refused, because a successful retry gives it straight back. The 402 copy is therefore "update your card", never "resubscribe". _Avoid_: lapsed, expired — those now fall back to free instead. |
| **Fallback to default** | What a *terminal* subscription end does: the webhook moves the row to the **Default tier** with status `active`, and the **Quota period** back to our monthly roll (ADR-0018). An ex-customer becomes a free user rather than someone with less than a stranger. `stripeCustomerId` is kept, `stripeSubscriptionId` cleared. _Avoid_: downgrade (also a paid-to-paid move), cancellation (Stripe's event, not our reaction to it). |
| **Tier-less subscription** | A **Subscription** row whose `tier_id` is `null`: the user has an account, a window and their Stripe customer id, and no **Tier** to read an **Entitlement** from ([ADR-0032](adr/0032-every-tier-is-deletable-and-an-empty-catalog-is-a-state.md)). Reachable one way only — an operator deleted the tier they were on and the catalog has no **Default tier** to move them to — which is why the denial states the condition rather than its cause. **The row survives rather than the subscription being deleted**, deliberately: `stripeCustomerId` is what stops a returning payer becoming a stranger with the same email, and `created_at` is the anchor every future **Quota period** is rolled from, so destroying the row would move that user's `resetAt` for ever. `/api/me` and `POST /api/relist/authorize` both answer **`NO_TIER`**. It ends **two ways**: `makeDefault` ends it for everybody at once, and since T78 the holder can end their own by **buying a plan** — the popup shows them the catalog rather than a wait, because deleting the *default* tier strands accounts while leaving every other tier on sale. Only where the catalog is empty is waiting on an operator the whole of the answer. **Not the same as "no subscription"**, which ADR-0014 made unreachable and this does not revive — there is still exactly one row per user. _Avoid_: no subscription, unsubscribed, orphaned user (the *subscription* is orphaned, not the person). |
| **`NO_TIER`** | The denial a **Tier-less subscription** gets, on `/api/me` as well as on the gate ([ADR-0032](adr/0032-every-tier-is-deletable-and-an-empty-catalog-is-a-state.md)). **Never `NO_PLAN`** — a **Plan** is a Tier joined with a Price, so a free user has a Tier and has never had a Plan, and the code would be true of them on a good day. States a condition and not its cause, like every code beside it; `TIER_WITHDRAWN` was the alternative and would be the one naming an event. It travels on `/api/me` because that is the half a user actually meets: `display-state.ts` maps every other non-`200` to `unavailable`, so a code sent only to the gate would be read by nobody. Carries no field — what to fix is not the user's to fix. _Avoid_: NO_PLAN, NO_SUBSCRIPTION, TIER_DELETED. |
| **Stripe cleanup** | The queue that finishes a tier deletion in Stripe: one row per outstanding call — cancel a subscription, archive a Price, archive the Product — each with its own attempt count and last error, drained by a `@Scheduled` job ([ADR-0032](adr/0032-every-tier-is-deletable-and-an-empty-catalog-is-a-state.md)). **Enqueued in the delete's own transaction**, because once the row is gone `tier_price` has cascaded, the Product id was never stored and the ex-subscribers are indistinguishable from anyone else's orphans — the work is captured, never re-derived. **"Archive" is what "delete" means in Stripe**: `PriceService` has no `delete` at all, and a Product that ever held a Price cannot be deleted either. Clearing `metadata.tier_code` is the half that is not optional — archiving alone fires a `price.updated` still carrying the tag, which drafts the tier straight back — and `adopt` refuses a code while any row here is unfinished, which is a tombstone scoped to the window rather than for ever. _Avoid_: tier deletion queue (it is Stripe's half only), retirement, teardown. |
| **Payment method** | What a buyer picks on the Stripe Checkout page: iDEAL, PayPal, card, SEPA. A setting on the Stripe **account** and never a parameter in code — `OpenCheckout` sets no `payment_method_types`, so adding one is a dashboard checkbox rather than a deploy (ADR-0006, amended 2026-09-01). Distinct from the **processor**, which is Stripe and of which there is exactly one: PayPal is a method *inside* Stripe, not a second processor, and every mirror, webhook, portal and price column in this system assumes that. _Avoid_: payment provider — conflating method with processor is what makes "add PayPal alongside Stripe" read as either a checkbox or a quarter of work. |
| **Brand name** | What users see, held in one root `brand.json` and read at build time by `manifest.template.json`, the popup, `apps/web` and the login theme. **Provisional until T60 (#91)**, and deliberately not spelled here: this entry used to name it, the name changed in `brand.json`, and the copy in this line went on saying the old one — which is the drift the file exists to prevent, found in exactly the place that is hardest to notice. Distinct from **`mprelist`**, the internal identifier frozen into `com.mprelist`, `@mprelist/*`, the Keycloak realm and its three clients, and the Postgres database. Renaming the brand is one file and a rebuild; renaming the identifier is a repo-wide refactor and a `down -v`. Never lead the brand with "Marktplaats" — Web Store policy forbids trademark use that implies endorsement. **The mark is part of it**: `brand.icon` names one square master in `brand/`, and every size Chrome's manifest and the site's `<link>` tags declare is resized from it at build time by `@mprelist/ui/icon-png`, so no derivative is drawn by hand and a redraw is the same one-file edit a rename is. **The test is drift, not whether a file is in git**: the **Keycloak theme**'s output *is* committed, because the local stack bind-mounts it straight out of the working tree and so it must exist without a build having been run, and CI rebuilds it and fails on any difference — which makes it a cache of this file rather than a second copy of it. Until T81 the reason given was that a deployed Keycloak read it out of that host's git checkout; [ADR-0034](adr/0034-the-deployment-tree-ships-with-the-tag.md) ended the checkout and not the rule. **The test is who reads it.** What a *user* reads is the brand's — the manifest's name and description, the popup header, the site's header and footer, the legal copy, and the sign-in card and its footer. What an *operator* reads is the identifier's — the **Keycloak theme**'s name, both realms' `displayName`, `com.mprelist`, `@mprelist/*` and the database. `displayName` is the case that *proved* the rule rather than an instance of it: it sat on the user's side of that line, was copied there by hand, and read `Bumpr` for as long as nobody looked — so [ADR-0033](adr/0033-the-login-page-is-ours-and-is-generated.md) moved the *page* off it instead of keeping the copy in step, and since T60's sweep the field itself is the identifier's, like the theme name beside it. This is the rule the next label to be invented is decided by — an email theme, a Stripe Product, an SMTP `From`. _Avoid_: conflating the two. |
| **Keycloak theme** | The theme every Keycloak page of this product's is drawn in — `apps/keycloak-theme`, generated from `brand.json` and `@mprelist/ui` ([ADR-0033](adr/0033-the-login-page-is-ours-and-is-generated.md)). Named `mprelist`, because a theme is something an administrator picks out of a list and so is the identifier's, not the brand's. **One theme, many *types***: a type is Keycloak's own unit — `login` today, `email` next — with its own properties, resources and templates, so adding one is a directory under `src/` and a line in the registry rather than a second workspace. It is `parent=base` plus one replaced `template.ftl`: Keycloak's own templates carry the flow and this theme decides what their `kc…Class` hooks *are*, which is how the field on that page becomes `.mp-input` rather than something drawn to look like one. **Its build output is committed**, the only one in this repository, and both stacks bind-mount that same directory — which is why no Keycloak image of ours exists, and why CI rebuilds the directory and fails on any difference. _Avoid_: "the Keycloak page" — it is a surface of this product, and the account and admin consoles, which are not, keep Keycloak's own. _Avoid_ "login theme" for the workspace: `loginTheme` is the realm setting that points one **type** of this theme at the sign-in flow. |
